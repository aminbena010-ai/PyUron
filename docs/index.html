Bienvenido a PyUron V1.0.0

PyUron es un motor de videojuegos modular, Python-first, para 2D y 3D. No es un simple wrapper de Pygame: está construido desde cero en Python con renderizado OpenGL 3.3+ (Core Profile), escenas de nodos jerárquicas, física, audio, input y serialización JSON.

Su objetivo es que puedas pasar de la idea al prototipo jugable sin pelear con configuración de bajo nivel, pero conservando control real sobre el pipeline de render y la arquitectura del juego.

Python 3.12+ OpenGL 3.3+ Core 2D y 3D Licencia MIT

¿Qué es y para quién es?

PyUron está pensado para desarrolladores, estudiantes y creadores que quieren entender y controlar un motor de juego en Python sin renunciar a un render moderno. Es útil para prototipos, proyectos pequeños y para aprender cómo se conectan ventana, escena, render, física y assets.

Para aprender

Código legible y módulos separados por responsabilidad: ideal para estudiar el ciclo de un motor.

Para prototipar

Escenas 2D/3D, sprites, texto, física y audio listos para un demo jugable.

Para extender

Sistema de nodos y serialización registrable para añadir tus propios componentes.

¿Qué incluye?

Ventana y contexto

pygame-ce + PyOpenGL con Core Profile 3.3+, VSync y redimensionado.

Escenas de nodos

Node, Node2D, Node3D y Scene con jerarquía padre-hijo.

Render 3D

Shaders GLSL 330, iluminación Blinn-Phong y carga de modelos .obj.

Render 2D

Sprites, animaciones, texto, anclajes y batching por z_index.

Física

AABB, cajas y esferas, rebote, fricción, gravedad y raycast.

Audio

Música, SFX multicanal y generación de tonos procedurales.

Input

Mapa de acciones para teclado y ratón: is_action_pressed("jump").

Serialización

Guardado y carga de escenas completas en JSON.

Diagnóstico

Logs con colores, métricas de FPS y errores legibles.

¿Cómo funciona?

Todo gira alrededor del árbol de nodos

Una Scene es la raíz de un árbol de Node. En cada frame el motor recorre el árbol, actualiza cada nodo y recoge automáticamente la cámara activa y las luces. El render se hace en dos pasadas: primero 3D (mallas con iluminación) y luego 2D (sprites ordenados por z_index).

  1. Inicialización Se crea la ventana, el contexto OpenGL y el sistema de audio.
  2. Bucle principal Tick del reloj, eventos de input, callbacks on_update.
  3. Actualización scene._process(dt) avanza física y llama a update(dt) en los nodos.
  4. Render begin_frame → escena → end_frame → swap de buffers.
  5. Métricas FPS, tiempo de frame y tiempo de dibujo en consola.

Inicio rápido

Clona el repositorio e instala el entorno con uv (recomendado):

git clone https://github.com/aminbena010-ai/PyUron.git
cd PyUron
uv sync --extra dev
uv run python main.py

Con pip y un entorno virtual:

python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python main.py

Cómo usarlo

Una escena mínima necesita un Engine, una Scene y una cámara:

from pyuron import Engine, EngineConfig, Scene, Camera2DNode

engine = Engine(EngineConfig(title="Mi juego"))

scene = Scene("Nivel 1")
cam = Camera2DNode("Cam")
cam.size_y = 12.0
scene.add_child(cam)

engine.set_scene(scene)
engine.run()

La configuración de la ventana vive en EngineConfig (tamaño, título, VSync, versión de OpenGL y color de fondo). Los nodos se añaden con add_child y se actualizan sobrescribiendo update(dt).

Ejemplo incluido

El repositorio incluye 2D Coin Collector: un jugador animado, monedas giratorias, HUD interactivo, física 2D y guardado/carga de estado en JSON. Lánzalo desde main.py. Así se construye un jugador con AnimatedSprite2D:

from pyuron import AnimatedSprite2D, Camera2DNode, Scene, Vector3

player = AnimatedSprite2D(
    textures["player"], sprite_shader,
    frame_w=32, frame_h=32, name="Player",
)
player.size = (1.5, 1.5)
player.fps = 8.0
player.z_index = 10

scene = Scene("Demo2D")
scene.add_child(player)
scene.add_child(Camera2DNode("Cam"))

CarpetaResponsabilidad

pyuron/physics/Colisiones, formas y raycast

tests/Pruebas unitarias (sin ventana gráfica)

Casos de uso

Prototipos jugables

Prueba mecánicas 2D con sprites, física y HUD; guarda el estado de la escena en JSON.

Demos 3D

Escenas con mallas .obj, luces direccionales/puntuales y cámara en primera persona.

Docencia

Base para explicar render, jerarquías, colisiones y bucles de juego en Python.

Herramientas propias

Extiende nodos y registra tipos para serialización; construye editores o visores.

Limitaciones actuales

Las colisiones usan AABB (sin rotación avanzada). El backend de ventana y eventos sigue siendo pygame-ce. No hay todavía una API de scripting separada ni un editor visual completo.
